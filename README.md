# Цифровая визитка backend-разработчика

GraphQL API с профилем Даниила Белякова, опытом, навыками и проектами. Приложение использует Node.js, TypeScript, NestJS, Apollo, Prisma и PostgreSQL; запуск полностью описан через Docker Compose.

## Запуск

Установите Docker и Docker Compose. Скопируйте `.env.example` в `.env`, задайте длинный случайный пароль из латинских букв и цифр и при необходимости измените `APP_PORT`. Затем выполните:

```sh
docker compose up --build -d
```

Откройте Apollo Sandbox по адресу `http://localhost:3000/graphql` (или используйте выбранный порт). При старте приложение ждёт готовности базы, применяет версионированные миграции и добавляет профиль, если его ещё нет. Данные PostgreSQL сохраняются в томе Docker между перезапусками. Повторный запуск не дублирует профиль и не перезаписывает существующие данные.

```graphql
query {
  profile {
    name
    description
    links { label url }
    skills { name }
    experience { company position period achievements }
    projects { name description url }
  }
}
```

Чтобы остановить приложение, выполните `docker compose down`. Тома при этом сохраняются. Для локальной разработки можно установить зависимости командой `npm ci`, задать `DATABASE_URL`, выполнить `npx prisma migrate deploy`, `node prisma/seed.js` и запустить `npm run dev`. Тесты: `npm test`; проверка сборки: `npm run build`.

## Архитектура

GraphQL resolver отвечает за API, сервис — за сценарий получения профиля, репозиторий — за доступ через Prisma. Модели профиля, ссылок, навыков, опыта и проектов разделены внешними ключами. У проекта ссылка необязательна: закрытому или неопубликованному проекту не придумывается адрес.

Поскольку API возвращает единственный профиль, репозиторий заранее загружает его связи одним вызовом Prisma. Это исключает отдельные запросы из резолвера на каждый элемент и проблему N+1; при этом даже если клиент запросил только имя, связи тоже будут загружены. Для одного небольшого профиля это осознанное упрощение; при росте объёма или появлении списка профилей стоит перейти к выборке по запрошенным полям и пакетной загрузке связей.

Миграции хранятся в репозитории и применяются до запуска сервера. Начальные данные добавляются в транзакции только при отсутствии профиля; это сохраняет последующие изменения, но обновление seed-файла само по себе не меняет уже созданную запись. База доступна только внутри сети Compose; наружу публикуется только порт API. Apollo Sandbox и introspection включены для демонстрации тестового задания.
